🧱Protéger un réseau : pare-feu, DMZ, VPN

Filtrer le trafic, isoler les serveurs exposés à Internet et connecter les salariés à distance en toute sécurité.

Le pare-feu filtre le trafic

Il compare chaque paquet à une liste de règles, de haut en bas. La première règle qui correspond s'applique.

#SourceDestinationPortAction
1LANInternet80, 443 (web)Autoriser
2LANServeur DNS53Autoriser
3InternetServeur web DMZ443Autoriser
4AdminServeurs22 (SSH)Autoriser
5ToutToutToutRefuser
Règle d'or : tout ce qui n'est pas explicitement autorisé est interdit (la dernière règle « refuser tout »). On n'ouvre que le strict nécessaire.
📋

Sans état

Regarde chaque paquet seul (IP, port).

🧠

Avec état (stateful)

Suit les connexions : autorise automatiquement les réponses à une connexion sortante.

🔬

Applicatif / UTM

Analyse aussi le contenu (filtrage web, antivirus…).

Exemples de pare-feu : pfSense, OPNsense, Stormshield, Fortinet. Sous Linux : iptables/nftables, ufw.

La DMZ : une zone tampon

Les serveurs accessibles depuis Internet (site web, messagerie) sont placés dans une zone isolée : la DMZ. S'ils sont piratés, l'attaquant n'est pas dans le réseau interne.

FluxAutorisé ?
Internet → DMZ (sur le port du service, ex 443)✅ Oui
Internet → LAN❌ Jamais
LAN → DMZ✅ Oui (pour administrer, consulter)
DMZ → LAN❌ Non (ou très limité)
LAN → Internet✅ Oui (web), souvent via un proxy

Les autres briques de défense

🚪

Proxy

Intermédiaire pour la navigation web : filtre les sites, journalise.

🚨

IDS / IPS

Détecte (IDS) ou bloque (IPS) les comportements suspects. Ex : Suricata.

🦠

Antivirus / EDR

Protège chaque poste et serveur.

📶

Wi-Fi sécurisé

WPA3 (ou WPA2) ; réseau invités séparé. Jamais WEP.

C'est la défense en profondeur : plusieurs couches de protection, pour qu'une seule faille ne suffise pas.

VPN : un tunnel chiffré à travers Internet

Un VPN (réseau privé virtuel) crée un tunnel chiffré : les données traversent Internet mais personne ne peut les lire.

🧳 VPN nomade (accès distant)

Un salarié en télétravail se connecte au réseau de l'entreprise depuis chez lui, comme s'il était au bureau.

🏢↔🏢 VPN site à site

Relie deux sites de l'entreprise (siège et agence) de façon permanente, entre deux routeurs / pare-feu.

Les protocoles

ProtocoleÀ retenir
IPsecStandard, très utilisé en site à site
OpenVPNLibre, basé sur TLS, très répandu (pfSense)
WireGuardModerne, simple et très rapide
PPTP❌ Obsolète, n'est plus sûr
Le VPN protège les données pendant le trajet. Il ne protège pas un poste déjà infecté : il faut aussi un antivirus, des mises à jour et une authentification forte (MFA).
