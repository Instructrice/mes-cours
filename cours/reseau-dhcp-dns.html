🛎️Services réseau : DHCP et DNS

Les deux services sans lesquels rien ne marche : donner une adresse IP automatiquement, et traduire les noms en adresses.

DHCP : l'IP automatique

Le serveur DHCP distribue automatiquement la configuration réseau aux clients. Ports UDP 67 (serveur) et 68 (client).

Les 4 étapes : D.O.R.A.

  1. Discover 📢 Le client crie en broadcast : « Y a-t-il un serveur DHCP ? »
  2. Offer 🎁 Le serveur propose : « Je te propose 192.168.1.50 ».
  3. Request 🙋 Le client répond : « D'accord, je prends celle-là ».
  4. Ack ✅ Le serveur confirme : « C'est à toi pour 8 jours ».

Ce que le serveur donne

🔢

Adresse IP + masque

Prise dans l'étendue (plage d'adresses).

🚪

Passerelle

Pour sortir du réseau.

📖

Serveur DNS

Pour résoudre les noms.

⏳

Durée du bail

L'adresse est prêtée, pas donnée. Le client renouvelle.

📌 Réservation

Toujours la même IP pour une machine, liée à son adresse MAC. Idéal pour une imprimante.

🔁 Relais DHCP

Le broadcast ne traverse pas les routeurs. Le relais (ip helper-address) transmet les demandes vers le serveur d'un autre réseau.

Les serveurs ont une IP fixe configurée à la main, jamais en DHCP : on doit toujours les retrouver à la même adresse.
# Windows : libérer puis redemander une adresse C:\> ipconfig /release C:\> ipconfig /renew C:\> ipconfig /all # voir la config complète

DNS : l'annuaire d'Internet

Il traduit un nom (www.exemple.fr) en adresse IP (93.184.215.14). Port 53 (UDP surtout).

Une hiérarchie en arbre

Les enregistrements à connaître

TypeRôleExemple
ANom → IPv4www → 192.0.2.10
AAAANom → IPv6www → 2001:db8::10
CNAMEAlias vers un autre nomintranet → srv-web
MXServeur de messagerie du domainemail.exemple.fr
NSServeur DNS qui fait autoriténs1.exemple.fr
PTRIP → nom (résolution inverse)192.0.2.10 → www

Comment se passe une résolution

  1. Le PC regarde son cache (et le fichier hosts).
  2. Sinon il demande à son serveur DNS (donné par le DHCP).
  3. Ce serveur interroge la racine, puis le serveur du .fr, puis celui d'exemple.fr.
  4. Il renvoie l'IP au PC et la garde en cache (durée = TTL).
C:\> nslookup www.exemple.fr C:\> ipconfig /flushdns # vider le cache DNS $ dig www.exemple.fr # sous Linux
« Internet ne marche plus » mais ping 8.8.8.8 fonctionne ? C'est souvent le DNS le coupable 😉
